Claude Code skill · live recording flow

record-agent-testThe agent performs the test.
The recorder writes it.

A background recorder owns a real Chromium and streams a Playwright test as the page is driven. Claude Code itself drives that page over CDP — one subcommand per action — so the generated *.spec.ts covers exactly what was asked. No API key, no embedded model loop. Optionally, the test is replayed and filmed into a screencast.

/ 01 — system

The wiring

Two processes, one browser. The agent connects to the recorder-owned browser and acts on the page; the recorder listens to the page's DOM events and doesn't care which CDP client caused them — so every action becomes a recorded test step. The generated spec can then be replayed and filmed.

agent → browser, over CDP (actions & snapshots) recorder taps DOM events generated test, written live your goal optional screencast (WebM)
/ 02 — flow

The whole run, phase by phase

One command boots the rig, Claude Code drives the loop, one command tears it down and prints the test — and optionally films it. Everything coordinates through small files in .run/.

01

Start the rig session.mjs start

Boots the moving parts in the background and hands the agent a first look at the page.

  • Makes .run/, clears stale recorder-ready / stop / assertion.json / session.json.
  • If the form URL isn't already served, spawns server.mjs detached on :5188 (skips it for a real app that's already up).
  • Spawns recorder.mjs detached: launches Chromium with --remote-debugging-port=9333, calls context._enableRecorder(), opens the form, writes .run/recorder-ready.
  • Waits for ready, records PIDs in session.json, connects over CDP, and prints a snapshot of every control + [data-testid] region.
02

Drive the page — the agent loop

Claude Code reads the snapshot, decides the next move from the goal, and runs one subcommand per action. Each connects over CDP, performs a high-fidelity Playwright action, settles, disconnects (closing only its CDP client — the recorder keeps the browser), and prints a fresh snapshot. Repeat until the goal is met.

  • Do exactly what's asked. “Only the email field” touches only the email field; no submit unless implied.
  • Remember the values typed — they become the test's real, input-derived assertion.
  • Each step is captured by the recorder the instant its DOM event fires → generated.spec.ts grows live.
03

Finish & assert session.mjs finish

Declares the success criterion and tears the rig down cleanly.

  • If given --assert-testid / --assert-contains, writes .run/assertion.json.
  • Writes .run/stop. The recorder waits ~900ms (so the throttled writer flushes the last action), context.close() finalizes the test, then it exits.
  • Waits for the recorder PID to die, then enriches the raw recording via postprocess.mjs: a real title + the assertion as expect(…).toBeVisible() / .toContainText(…).
  • Stops the server, prints the test. With RUN_GENERATED=1, runs npx playwright test right away.
04

Optional: film it RECORD_SCREENCAST=1

Replays the generated spec into an annotated WebM — a mouse cursor that animates between action points and a title overlay on each step, paced by SCREENCAST_SLOWMO.

  • Runs a copy of the spec with the screencast fixture swapped in — the real tests/generated.spec.ts stays untouched.
  • Uses page.screencast.start() + showActions({ cursor: 'pointer' }); saved to recordings/*.webm.
  • The replay also verifies the test passes, so it doubles as the run.
05

Result — a passing, asserted test (and a video)

A scoped tests/generated.spec.ts exists, green, asserting an input-derived outcome — so it fails if the form silently drops input rather than passing on a static string — plus, if requested, a recordings/*.webm walkthrough.

/ 05 — why these exact actions

Recorder-fidelity rules

Driving a recorder-attached page programmatically hits sharp edges a human mouse never does. The subcommands encode the fixes so the recording stays clean.

the wire

Open a CDP port, not the pipe

--remote-debugging-port=9333 lets a separate process connectOverCDP and share the very browser the recorder owns.

radios / checkboxes

Plain .click(), not .check()

The recorder delays the default action, so .check()'s built-in verify reads a stale false and throws. A click is recorded as .check().

dropdowns

.click() then .selectOption()

selectOption alone sets the value with no pointer event, so the recorder mis-anchors to the previously focused control. The click anchors it.

text fields

Plain .fill()

Anchors correctly on its own — no pre-click needed.

assertions

Injected, not recorded

Codegen records actions, not assertions. The agent's declared success criterion is baked in by postprocess.mjs as an expect.

the file writer

The Inspector writes the file

Only the real RecorderApp flushes outputFile. Headless runs just hide its window via PWTEST_CLI_HEADLESS=1.

/ 07 — output

What lands on disk

The steps are recorded verbatim — note the first one opens the modal that holds the form. The highlighted lines are the assertion the agent declared: it checks the name it typed, echoed back into the page's status region.

tests/generated.spec.ts
import { test, expect } from '@playwright/test';

test("fills and submits the signup form, then sees the created account confirmation", async ({ page }) => {
  await page.goto('http://localhost:5188/');
  await page.getByTestId('open-form').click();          // open the modal
  await page.getByRole('textbox', { name: 'Full name' }).fill('Ada Lovelace');
  await page.getByRole('textbox', { name: 'Email' }).fill('ada@example.com');
  await page.getByLabel('Role').selectOption('engineer');
  await page.getByRole('radio', { name: '+ years' }).check();
  await page.getByRole('textbox', { name: 'Anything we should know?' }).fill('Excited to join the team!');
  await page.getByRole('checkbox', { name: 'Subscribe to the product' }).check();
  await page.getByRole('button', { name: 'Create account' }).click();

  // Asserted automatically: the agent considered the run successful once this appeared.
  await expect(page.getByTestId("form-status")).toBeVisible();
  await expect(page.getByTestId("form-status")).toContainText("Account created for Ada Lovelace");
});
/ 08 — optional

Film the test — an annotated screencast

Set RECORD_SCREENCAST=1 before finish and the generated spec is replayed slowly and recorded to recordings/*.webm — with a mouse cursor that animates between action points and a title overlay on each step (Playwright's page.screencast API).

recordings/…confirmation.webm · 1280×800 · VP8 · slow-mo
how the frame is built
  • start — screencast.start({ path, size }) records the WebM to disk.
  • decorate — showActions({ cursor: 'pointer' }) draws the pointer that travels between action points + a per-step title.
  • pace — SCREENCAST_SLOWMO (default 500ms) spaces the actions so each is legible; a raw run is ~1–2s.
  • safe — a copy of the spec is filmed; the real generated.spec.ts never changes, and the replay verifies it passes.
shell
# add RECORD_SCREENCAST=1 to finish
RECORD_SCREENCAST=1 node session.mjs finish \
  --assert-testid form-status \
  --assert-contains "Account created for Ada"
